## Bloqueos

### B1. La limpieza puede declarar sesiones revocadas que siguen vivas
`hosted-profile-proof.mjs`, rama `cleanup-own-test-sessions`:

```js
if(error&&error.status!==401&&error.status!==403&&error.status!==404)throw Error('cleanup failed');
```

`signOut(jwt,'local')` necesita un access token vigente. El token dura cerca de 1 hora por defecto. Si la limpieza corre después:
- GoTrue responde 401.
- El script lo trata como éxito y borra los archivos locales.
- Escribe `own_sessions_revoked:3`.

Pero la sesión en `auth.sessions` y su refresh token siguen válidos. Además, si el navegador usó el `browser-state`, supabase-js rotó el refresh token, así que el archivo ya no refleja el estado actual. El recibo quedaría afirmando algo falso, lo que contradice la regla de reporte honesto.

**Fix exacto:**
1. En `create`, guardar `claims.session_id` de cada sesión en `private-receipt.json`. No es una credencial.
2. En `cleanup`:
   - Si `claims.exp*1000 <= Date.now()+30000`, refrescar con un cliente anon (`refreshSession({refresh_token})`).
   - Verificar `user.id` y llamar a `signOut(nuevoToken,'local')`.
   - No aceptar 401, 403 ni 404 como éxito.
3. Después del `signOut`, comprobar que `refreshSession` con el último refresh token falla.
4. Si algo no se puede verificar:
   - No borrar ese par de archivos.
   - Registrar `own_sessions_pending` con el `session_id`.
   - Revocar del lado del servidor solo con `delete from auth.sessions where id=$session_id and user_id=$uid`. Así sigue acotado a sus propias sesiones y no toca otros dispositivos.
5. `own_sessions_revoked` debe contar solo las revocaciones verificadas.

### B2. El `catch` borra archivos que el script no creó
La precondición revisa `private-receipt` y `session-i`, pero no `browser-state-i`. Si existe un `browser-state-0.json` previo:
- `writeFileSync(...,{flag:'wx'})` falla.
- El `catch` hace `unlinkSync` de `browser-state-0.json`, que no es suyo.

**Fix:**
- Agregar `browser-state-i.json` a la precondición `existsSync`.
- Registrar en `newlyCreated` cada ruta escrita con éxito, y borrar en el `catch` solo esas rutas.
