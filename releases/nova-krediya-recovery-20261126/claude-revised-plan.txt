## Blockers

**B1. `restart.sql:27-32` has no 60s grace after the lease expires.** Any lease past `lease_until <= now()` is renewed, even 1 ms after it expires. So the plan's claim that the original operation is fenced off is not true in the SQL yet.
- **Fix:** if `lease_until > now() - interval '60 seconds'` and `lease_until <= now()`, return null. Renew only when `lease_until <= now() - 60s`.
- **Test:** add a PGlite test for the 0–60s window.

**B2. The idempotent return in `restart.sql:27-28` doesn't prove a renewal happened.** `lease_until>now() and attempts>=2` also matches a live lease that was never renewed, for example after a normal second claim. Native would then run `exclusiveResume`, which skips the 2h guard, without any real renewal. This also clears up the unclear "currentattempt>=2" versus "up to 3" wording.
- **Fix (native only, no schema change):**
  - Only start once the lease has been expired for more than 60s.
  - Before the RPC, persist `restartPending:{expectedAttempts: job.attempts+1, expiredLeaseUntil}`.
  - Accept the result only if `attempts===expectedAttempts`, `lease_id` is unchanged, and `lease_until > max(now+10s, expiredLeaseUntil+60s)`. Anything else goes to review.

**B3. Renewal doesn't check service hours.** A renewal at 19:58, or outside hours, uses up a server attempt, and then `send()` stops with `OUTSIDE_SERVICE_HOURS`. `status()` in `engine.mjs:69` also lets this recovery start automatically, so this can happen without anyone triggering it.
- **Fix:** both the gateway `restart` action and native, before the RPC, must require `hours(now())` and `hours(now()+300000)`.
