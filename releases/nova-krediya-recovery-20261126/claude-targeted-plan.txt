## Blockers

**1. The real root cause hasn't been found.**
- The current reason, `RECOVERY_NOT_CONFIRMED` since 18:59, comes from the catch in `engine.mjs:52`. That catch replaces every error except `BROWSER_READ_INCOMING_FAILED`.
- At 18:59 the lease was still valid (it ran to 19:03). So the existing recovery path already ran and failed: it reads the journal, which has the right `name` shape (`pilot-journal.mjs:15`), then calls `recoverName` and `resumeDocument`.
- The first run also stopped at the name send (`send_intent authorized_name`, then `stopped`).
- So the name step has failed twice. The expired lease came after that and is a symptom. Possible causes include:
  - the name not being returned (`AUTHORIZED_NAME_UNAVAILABLE`, from the regex check at worker:169);
  - a compose failure on the name (`DRAFT_PRESENT`/`UNEXPECTED_DRAFT`);
  - `NO_PENDING_NAME_PROMPT`.
- If the cause is any of these, a fresh greeting will reach the same step and fail again, using up attempts 2 and 3.
- **Fix:** before patching, read the error code locally without exposing personal data: the `readDiagnostic` the driver saves, and `recoveryStep`. Also make `fail()` keep the real error code.

**2. A crash right after the renewal could resume the old conversation.** Once the lease is renewed, the existing branch at `engine.mjs:52` (job running, current lease, journal resumes at the document step, then `recoverName`) would run on any restart. It could send the name into the old conversation. Any `restartPending` state has to skip that branch and either continue the restart or go to review.

## Required changes to the plan

- **Change the order** so a failed check doesn't use up an attempt:
  1. Check the journal shape.
  2. Run `verifyView`.
  3. Run the read-only baseline check: last outgoing message equals the job's document, the last incoming is a name prompt from the provider, and the draft is empty.
  4. Persist `restartPending`.
  5. Call `restart-expired`.
  6. Rotate the journal and open a new one.
  7. Run `verifyView` again (`sendText` needs a check within the last 15 s).
  8. Send the fresh greeting.
- **Driver:** pass the document into `baseline`, since the driver doesn't know it today.
- **Gateway:** add `restart-expired` to the route regex (`worker:127`) and the RPC allowlist (`worker:118`). Accept only `{id, lease_id}`.
  - Require `operating` and `hours(now())`.
  - Read the job and check that its lease matches.
  - Check consent and source with `validConsent` and `verifySource`. Don't use `current()`, because it rejects expired leases.
- **SQL (`restart.sql`):** the logic looks right: same lease, a cap of 3, the idempotent case, consent with more than 6 minutes left, the channel still held, no reset. Two caveats:
  - The `receipts` join could match more than one row; use `exists`.
  - Confirm `updated_at` exists, and record the renewal wherever the existing audit trail lives.
- **Timing:** a 5-minute lease against 225 s of conversation plus 30 s of closing leaves little margin. Make sure `finish` runs before the lease expires.
- **UI timing:** a 2-minute threshold would label normal waiting as technical, because a job can wait about 5 minutes behind another one. Use 10 minutes or more, counted from the later of `createdAt` and the 8:00 opening.
- **UI placement:** add the technical item for the store before the generic message at `worker:110`. Approved references already produce no "waiting" notice (`worker:85`).
